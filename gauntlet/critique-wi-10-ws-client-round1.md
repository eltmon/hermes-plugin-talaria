## Criteria
- CORRECTNESS: Not met. Documented envelopes that the encoder *does* emit match CP-3 (`Request` with `id` + `tag`=method + `payload` + `headers:[]`, `Interrupt` with `requestId`, `Ping`/`Pong`, unary `Exit`, streaming `Chunk.values`). Handshake URL is `ws(s)://{host}/ws?wsTicket=…`; http→ws / https→wss. Unary `server.probe` / `projects.listEntries` round-trip. Expo backoff is 1, 2, 4, … capped at 30s via injected `sleep` (wall 0.0001s on a 7s fake wait). Ticket rejection retries once with a fresh `ticket_fn()` and no backoff, then raises `TicketRejected`. That is not enough for AC2 streaming against the live protocol. t3code serves WS via Effect `RpcServer.toHttpEffectWebsocket` → socket protocol `supportsAck: true`. After each `Chunk` the server latches and waits for `{"_tag":"Ack","requestId":…}` before the next chunk *or* the terminal `Exit` (`RpcServer.ts` `streamEffect`, `latch.await`). [`talaria/t3_ws.py`](/home/eltmon/Projects/hermes-plugin-talaria/talaria/t3_ws.py) never sends `Ack`. Independent Ack-gated peer: first `snapshot` chunk arrives, then the subscribe hangs (0.4s timeout); client sent `Ping`, `Request`, then `Interrupt` on close; `acks=[]`; second chunk and `Exit` never leave the server. Official Effect `RpcClient` sends Ack after every Chunk (`RpcClient.ts` ~559–571). This client will stall `orchestration.subscribeShell` / `subscribeThread` (WI-12) and any multi-chunk file stream on a real 0.0.37 socket. `_dispatch` also ignores `_tag: "Defect"` (and `ClientProtocolError`); a protocol defect hangs unary `request()` the same way.

- SECURITY: Met. [`tests/fixtures/frames/transcript.json`](/home/eltmon/Projects/hermes-plugin-talaria/tests/fixtures/frames/transcript.json) has no token / Bearer / secret / wsTicket / PEM / JWT. Tests use `tix-1` / `tix-2` as query values only. Client does not log the ticket. NFR-2 is not in play (no secret store on this item).

A fixture-driven fake server that does not implement Effect Ack backpressure cannot prove “streaming subscription round-trip” against the CP-3 socket.

## Defects
1. **Streaming client never Acks, so a live t3code WS server stalls after the first `Chunk`.** [`talaria/t3_ws.py:315`](/home/eltmon/Projects/hermes-plugin-talaria/talaria/t3_ws.py) `_dispatch` on `Chunk` only `queue.put`s values. Effect RPC over WebSocket (`supportsAck: true` in `makeSocketProtocol`) waits for `{"_tag":"Ack","requestId": <id>}` after each chunk before emitting the next chunk or `Exit`. Probe against an Ack-gated peer: subscribe received `[{kind: snapshot}]` then hung; no Ack on the wire. Fix: after delivering a Chunk to the stream queue, send that Ack (same `requestId`). Fail waiters on `_tag: "Defect"` / `ClientProtocolError` instead of dropping them. Document `Ack` next to Ping/Pong/Interrupt in the CP-3 section of [`docs/design.md`](/home/eltmon/Projects/hermes-plugin-talaria/docs/design.md). Do not invent extra envelopes (`interruptors` is decoded-only; encoded Interrupt is `{_tag, requestId}` as you already send).

2. **Fixture fake server and transcript omit Ack, so AC2 cannot catch defect 1.** [`tests/fixtures/frames/transcript.json`](/home/eltmon/Projects/hermes-plugin-talaria/tests/fixtures/frames/transcript.json) goes `Request subscribeShell` → two `Chunk`s → `Interrupt` with no client `Ack`. [`tests/test_ws.py`](/home/eltmon/Projects/hermes-plugin-talaria/tests/test_ws.py) `ScriptedWs._reply_request` enqueues every shell chunk up front. That is not the live protocol. Fix: add `{"dir":"out","raw":{"_tag":"Ack","requestId":"shell-1"}}` (or remapped id) to the transcript; make the fake server send chunk 2 / `Exit` only after an Ack for chunk 1 (Effect `latch.await`). Assert the client’s sent frames include those Acks. Keep the existing unary probe/listEntries tests and the mocked-clock reconnect/backoff + 2-try ticket-rejection tests — those are fine.
